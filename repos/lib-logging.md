# lib-logging

## Kind
A Spring Boot auto-configuration library (type `lib`) generated by java-skeleton. It gives every
servlet service the same logs: a correlation id and the tenant in the MDC, automatic request and
method logs with a level policy, and a fluent API for logs written on demand. It is technical only,
with no business logic. The tenant comes from `lib-tenant`, which is an optional dependency.

## Edit
- `src/` (main, test, intTest, archTest): the library code and its tests. The sample classes that
  java-skeleton generates (`LibraryInfo`, `LibraryAutoConfiguration` and their tests) may be
  replaced.
- `README.md`, only when usage, commands or flags change.

## Do not touch
- The Gradle wrapper (`gradlew`, `gradle/wrapper/`).
- The build configuration (`build.gradle`, `gradle/`, `gradle.properties`), the `Makefile` and
  `.github/`, unless the card is about the build.
- This repository has no `CONTRIBUTING.md` and no `DEVLOG.md`, on purpose: its README and the body
  of each PR cover them. Do not create them.
- `lib-errors` and `lib-tenant`: they are other repositories. If the card cannot be met without
  changing one of them, block and say so.

## Verify
`./gradlew build` in the repository (runs `test`, `intTest` and `archTest`, SpotBugs and the
JaCoCo coverage rule). JaCoCo counts only the unit tests (`test`) and requires 80% of lines: the
logic must be covered by unit tests, integration tests alone do not count. A criterion that needs
the library published locally is checked through a temporary Maven local, as `qa` does.
